# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Germanized for WooCommerce — a WordPress/WooCommerce plugin that adapts WooCommerce to German/EU legal requirements (unit prices, delivery times, legal checkboxes, price labels, revocation, GPSR/product safety, food info, deposits, SEPA direct debit, e-invoices).

Minimums: PHP 5.6 (bootstrap) / 7.4 (composer platform), WP 5.4, WooCommerce 3.9. Text domain: `woocommerce-germanized`. Node `^20.11.1`.

## Commands

### JS/CSS build (`@wordpress/scripts` + custom webpack config)
```bash
npm run build          # production build into build/
npm start              # watch mode
npm run lint:js
npm run lint:css
npm run format
```
`build/`, `vendor/`, and `packages/` are gitignored — they are generated by `npm run build` and `composer install`.

### PHP tests (run inside Docker)
```bash
npm run docker-clean   # (re)create the wordpress_test container + DB — needed once, or after breakage
npm run phpunit        # full suite

# single file / single test — pass phpunit args through docker exec:
docker exec -it --workdir /var/www/html/wp-content/plugins/woocommerce-germanized wordpress_test \
  php ./vendor/bin/phpunit tests/unit-tests/product/gzd-product.php
docker exec -it --workdir /var/www/html/wp-content/plugins/woocommerce-germanized wordpress_test \
  php ./vendor/bin/phpunit --filter test_unit_price
```
Tests live in `tests/unit-tests/{api,order,product,util}`, bootstrapped by `tests/bootstrap.php` (loads the WP test lib, WooCommerce, and composer packages). CI (`.github/workflows/test.yml`) runs the matrix PHP 7.4/8.0/8.2 × Woo latest/6.4.1 using `tests/bin/install.sh`.

## Architecture

### Two class systems coexist

1. **Legacy `includes/`** — procedural functions + `WC_GZD_*` classes loaded by a custom `spl_autoload_register` in `WooCommerce_Germanized::autoload()` (`woocommerce-germanized.php`). Naming convention is strict: `WC_GZD_Foo_Bar` → `includes/class-wc-gzd-foo-bar.php`; `WC_GZD_Admin_*` → `includes/admin/`; `WC_GZD_Compatibility_*` → `includes/compatibility/`; `WC_GZD_Gateway_*` → `includes/gateways/<slug>/`.
2. **Modern `src/`** — PSR-4 `Vendidero\Germanized\` via the Jetpack autoloader, `Squiz.Classes.ClassFileName` enforced. Holds blocks, shipments bridge, shopmarks, DI container.

Both are live; new code generally belongs in `src/`, but anything hooking legacy templates/functions stays in `includes/`.

### Bootstrap order
`woocommerce-germanized.php` → `Autoloader::init()` + `Packages::init()` → `WooCommerce_Germanized` singleton (`WC_germanized()`). Load phases matter:
- `includes()` at construct time (core functions, install, admin, conditional frontend)
- `woocommerce_loaded_includes()` on `woocommerce_loaded` (legal checkboxes, product attributes, CLI)
- `init()` on `init` priority 0 (textdomain, settings, scripts, emails)
- Compatibility on `plugins_loaded` / `after_setup_theme` priority 0

Hooks `woocommerce_germanized_before_load`, `woocommerce_germanized_loaded`, `before_woocommerce_germanized_init`, `woocommerce_germanized_init` mark these boundaries.

### Shopmarks — how frontend output is placed
`src/Shopmarks.php` + `src/Shopmark.php` are the central mechanism for *where* Germanized renders legal info. Each location (`single_product`, `product_loop`, `product_block`, `cart`, `mini_cart`, `checkout`, `order`, `single_product_grouped`) registers typed shopmarks (`unit_price`, `delivery_time`, `legal`, `manufacturer`, …) with a default WP filter, priority, and template callback. Store owners override filter/priority/enabled state via `woocommerce_gzd_*` options, edited under the Shopmarks settings tab. When adding new frontend output, register a shopmark rather than hardcoding `add_action` — otherwise it is not repositionable and not covered by the settings UI.

### Product decoration
`WC_GZD_Product` (`includes/abstracts/abstract-wc-gzd-product.php`) is a **decorator** wrapping a `WC_Product` (`$child`), not a subclass. Obtain it via `wc_gzd_get_product( $product )`; instances are cached by `WC_GZD_Product_Factory`. Germanized-specific getters (unit price, delivery time, nutrients, allergenic, deposit type, manufacturer, safety attachments) live here. Variable/variation/grouped variants are in `includes/class-wc-gzd-product-*.php`.

Taxonomy-backed data (delivery times, manufacturers, deposit types) extends `WC_GZD_Taxonomy` (`includes/abstracts/abstract-wc-gzd-taxonomy.php`), with singletons exposed as `WC_germanized()->delivery_times`, `->manufacturers`, `->deposit_types`, `->nutrients`, `->allergenic`, `->units`, `->price_labels`.

### Templates
`templates/` mirrors WooCommerce's structure. `WooCommerce_Germanized::filter_templates()` hooks `woocommerce_locate_template` at priority 1500 and resolves: theme override (`yourtheme/woocommerce-germanized/...`) → plugin template. Checkbox templates fall back to `templates/checkboxes/default.php` when a configured custom template is missing. Filters: `woocommerce_gzd_template_name`, `woocommerce_gzd_default_plugin_template`, `woocommerce_germanized_filter_template`.

Template rendering functions are in `includes/wc-gzd-template-functions.php`; static hook wiring in `includes/wc-gzd-template-hooks.php` (both excluded from coverage).

### Legal checkboxes
`WC_GZD_Legal_Checkbox` (data object with `get_*`/`set_*` per property) + `WC_GZD_Legal_Checkbox_Manager` (registry, conditional display, validation per location: checkout, register, pay_for_order, reviews). Register via the `woocommerce_gzd_legal_checkboxes` flow / `$manager->register( $id, $args )`. Options persist as a single serialized array, not individual options.

### Blocks (WooCommerce Cart/Checkout blocks + product elements)
- PHP: `src/Blocks/` — `BlockTypesController` registers `src/Blocks/BlockTypes/*`; `src/Blocks/Integrations/` implements `IntegrationInterface` for Cart/Checkout/MiniCart/ProductElements.
- JS: `assets/js/blocks/{cart,checkout,cart-checkout,mini-cart,product-elements}`, shared code in `assets/js/base`, aliased in webpack as `@germanized/base-components`, `@germanized/product-elements`, `@germanized/base-hooks`, `@germanized/types`, `@germanized/settings`.
- `webpack.config.js` emits several bundles (main, frontend `-frontend.js`, style `-style.js`, `build/static/`) and reads block metadata to generate entries — adding a block usually means touching both the PHP block type and the webpack entry set.

### Compatibility layer
`includes/compatibility/` holds ~30 `WC_GZD_Compatibility_*` classes (WPML, Polylang, Elementor, Subscriptions, Product Bundles, PayPal Payments, …), each extending `WC_GZD_Compatibility` with a static `is_applicable()`. Registered through the `woocommerce_gzd_compatibilities` filter in `setup_compatibility()`. Theme compatibilities are handled separately via `setup_theme_compatibility()`. Prefer adding a compatibility class over scattering plugin-specific conditionals in core code.

### Shipments → Shiptastic
Shipment functionality has moved to the standalone Shiptastic plugin. `src/Shipments/*` are thin subclasses of `\Vendidero\Shiptastic\*`, `src/Shiptastic.php` re-maps every `woocommerce_shiptastic_*` hook back to the legacy `woocommerce_gzd_shipment*` names, and `includes/wc-gzd-shipments-legacy-functions.php` proxies `wc_gzd_*` shipment functions to `wc_stc_*` (returning falsy when Shiptastic is absent). Do not add new shipment logic here — it belongs in Shiptastic.

### Composer packages
`vendidero/eu-order-withdrawal-button-for-woocommerce` and `vendidero/woocommerce-eu-tax-helper` install into `packages/` (see `extra.installer-paths`). `bin/package-update.sh` runs on every composer install/update and **rewrites their text domains to `woocommerce-germanized`** and strips their vendor/readme files. Never edit `packages/` by hand — changes are overwritten.

### DB updates
`WC_GZD_Install::$db_updates` maps version → file in `includes/updates/`. A schema/data migration means adding `includes/updates/woocommerce-gzd-update-X.Y.Z.php` and registering it in that array.

## Conventions

- Options are prefixed `woocommerce_gzd_`; hooks `woocommerce_gzd_` (or `woocommerce_germanized_` for lifecycle hooks).
- Path/URL helpers: `WC_germanized()->plugin_path()`, `->plugin_url()`, `->template_path()`, and the `WC_GERMANIZED_ABSPATH` constant.
- HPOS (`custom_order_tables`) and `cart_checkout_blocks` compatibility are declared — order data access must go through CRUD APIs, never direct post meta.
- `wc_gzd_kses_post_svg()` and `wc_help_tip()` are registered as escaping functions in phpcs; other output must be escaped normally.
- Doc-block/commenting sniffs are disabled in `phpcs.xml`, but WordPress security/i18n/naming sniffs are enforced.
